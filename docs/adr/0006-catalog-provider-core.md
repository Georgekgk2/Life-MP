# ADR 0006 — Ядро каталогу та вендорів (Catalog & Provider Core)

- **Дата:** 2026-07-27
- **Власник ADR:** технічний власник Life-MP
- **Межі:** рішення встановлює архітектурну модель вендорів, модерації та публікації каталогу на базі Medusa v2.18.0 для розробки й тестового середовища. Воно не дозволяє комерційний запуск, реальний onboarding вендорів, приймання платежів чи оформлення замовлень.

## Контекст

Згідно з [ADR 0005](0005-search-and-cms.md), Payload CMS залишається заблокованим до проходження server-discovery gate та профільного load test. Тим часом проект потребує стійкого бекенд-джерела для структурування вендорів, лістингу товарів, модераційних статусів та ізольованого читання каталогу.

Згідно з рішеннями [launch scope](../decisions/launch-scope.md) (COM-1/2/3/5, LOG-1, CAT-1–5), будь-які комерційні транзакції, реальний onboarding, публічний знак якості чи регульовані твердження залишаються суворо заблокованими.

## Рішення

1. **Едине джерело правди для каталогу та вендорів:** Medusa v2.18.0 є єдиним джерелом правди для внутрішніх записів `Vendor`, модераційних рішень `CatalogListing`, прав прив'язаного `Product` та публікації у публічний каталог.
2. **Роль відсутнього Payload CMS:** Поки Payload CMS відсутній/заблокований, він не має жодного авторитету щодо товарів, категорій чи вендорів. Якщо в майбутньому Payload буде розгорнуто (після ADR 0005 gates), він керуватиме виключно редакційним контентом (статті, історії, гайди) та посилатиметься на стабільні ID з Medusa. Payload ніколи не може самостійно публікувати товари чи змінювати статус вендора.
3. **Синтетичні дані та fail-closed політика:**
   - У цьому етапі дозволено використання виключно синтетичних, некомерційних тестових даних для розробки та CI.
   - `CatalogListing.visibility` має лише значення `internal` та `local_demo`.
   - Публічний маршрут `GET /store/catalog` повертає локальні демо-товари лише тоді, коли `NODE_ENV` є `development` або `test`, і встановлено прапорець `ALLOW_SYNTHETIC_CATALOG=true`.
   - У виробничому середовищі (`NODE_ENV=production`) або за відсутності прапорця локальні демо-товари неприступні, а запит повертає порожній каталог.

## Наслідки

- Medusa керує модераційним циклом лістингів та правами доступу вендорів.
- Storefront читає каталог через єдиний серверний асистент і не показує елементів оформлення покупки чи кошика.
- Відсутність Payload CMS не перешкоджає розробці ядра каталогу.
