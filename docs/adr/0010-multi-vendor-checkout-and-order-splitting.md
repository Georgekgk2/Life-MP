# ADR 0010 - Мультивендорний кошик, єдина оплата та розщеплення замовлень (Варіант Б)

- **Дата:** 2026-07-27
- **Власник ADR:** технічний власник Life-MP
- **Статус:** Accepted (Прийнято для технічного Sandbox-проєктування; Legal/Fiscal = PENDING)

---

## Контекст

Замовник підтвердив бізнес-намір для першої версії платформи «ЛАЙФ» (**Варіант Б**):
Покупець повинен бачити один кошик та здійснювати **одну платіжну транзакцію** за товари кількох виробників. Надалі платформа розраховується з кожним виробником за договором.

Це рішення дає достатню підставу для проєктування **технічного ядра чекауту (Phase 4A)**. Проте, воно **не визначає автоматично** юридичного продавця (Merchant of Record vs Marketplace Agent), емітента фіскального чека чи договірного носія відповідальності за повернення.

---

## Затверджений бізнес-намір та технічна архітектура

1. **Затверджений бізнес-намір (Approved Business Intent)**:
   - Єдиний мультивендорний кошик та єдиний платіжний інтентивно-транзакційний чек для покупця.

2. **Затверджена технічна модель (Approved Technical Pattern)**:
   - `ParentOrder` (батьківське замовлення платформи) -> `VendorChildOrders` (дочірні замовлення для конкретних вендорів) -> `VendorPayableLedger` (внутрішній реєстр боргу платформи перед вендорами).

3. **Юридично-фіскальний статус (Legal & Fiscal Status = PENDING)**:
   - Статус юридичного продавця та фіскального чека залишається **PENDING LEGAL + ACCOUNTING + ACQUIRER CONFIRMATION**.
   - Невизначеними залишаються 3 варіанти:
     1. *Marketplace Agent / Payment Collection Model:* Продавцем залишається виробник, платформа приймає кошти як агент;
     2. *Merchant of Record:* Платформа виступає єдиним юридичним продавцем товару покупцю;
     3. *Hybrid:* Модель залежить від конкретної категорії SKU чи умов договору.

4. **Розщеплення замовлень (Order Splitting Workflow in Sandbox)**:
   - Після імітації успішної оплати у sandbox-режимі workflow розділяє кошик на `VendorChildOrders`.
   - Кожен вендор бачить у кабінеті лише свої позиції та генерує ТТН Нової Пошти для прямого відправлення (`vendor_direct`).

5. **Заборона в коді до юридичного погодження (Phase 4B)**:
   - Строго заборонено використовувати в UI або документах вирази «продавець ЛАЙФ» або «чек від ЛАЙФ».
   - Заборонено здійснювати автоматичні реальні виплати чи підключати бойовий ПРРО/еквайринг.

---

## Наслідки

- Дозволяє реалізувати **Phase 4A (Sandbox Commerce Core)**: `Cart`, `ParentOrder`, `VendorChildOrder`, `VendorPayable`, `SandboxPaymentAdapter`, `MockNovaPoshtaAdapter`, `MockFiscalAdapter`.
- Повна ізоляція юридичних ризиків до отримання офіційних висновків юриста й бухгалтера.
