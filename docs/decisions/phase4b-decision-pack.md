# Пакети рішень Phase 4B (Phase 4B One-Page Decision Pack & Questionnaires)

## Статус і Мета

Цей документ містить **робочі пакети рішень та структуровані опитувальники Phase 4B** для профільних фахівців (юриста, бухгалтера, фінансового директора, логіста). Заповнення та підписання цих пакетів є обов'язковою умовою для переходу до Phase 4C (Live Acquiring, Nova Poshta API, ПРРО).

## 2. Опитувальник для Юридичного радника (Legal Questionnaire)

> **Мета:** Формалізація договірних відносин маркетплейсу з майстернями та покупцями відповідно до законодавства України.

1. **Юридична модель платформи (COM-1 / LGL-1):**
   - Чи погоджується застосування **Агентської моделі (Marketplace Agent)** за ст. 295–305 ГКУ та ст. 1000 ЦКУ, за якою платформа надає посередницькі послуги, а договір купівлі-продажу укладається між покупцем і ФОП-майстернею?
   - _Відповідь:_ `[ ] Так, схвалено  [ ] Ні, застосувати MoR  [ ] Інше`
2. **Шаблони документів для публікації:**
   - Чи підготовлено шаблон **Публічної оферти купівлі-продажу для покупців**?
   - Чи підготовлено шаблон **Договору приєднання (агентського договору) для продавців-майстерень**?
   - Чи затверджено **Політику конфіденційності та обробки персональних даних (GDPR / ЗУ «Про захист персональних даних»)**?
3. **Політика повернень (LGL-2):**
   - Який порядок повернення якісного товару (14 днів за ст. 9 ЗУ «Про захист прав споживачів»): покупець відправляє посилку безпосередньо назад майстерні?
   - Хто компенсує логістичні витрати у разі повернення товару неналежної якості (брак)?

## 3. Опитувальник для Головного бухгалтера та Фінансового директора (Financial Questionnaire)

> **Мета:** Податкова оптимізація, первинні бухгалтерські документи та фіскальний облік.

1. **Визнання доходу та оподаткування (COM-1):**
   - Підтвердіть, що в дохід платформи «ЛАЙФ» зараховується виключно сума агентської винагороди (комісії), а транзитні кошти за товар не є об'єктом оподаткування платформи.
   - _Відповідь:_ `[ ] Підтверджено`
2. **Платіжний еквайр та розщеплення платежів (COM-2):**
   - Який провайдер обирається для інтеграції: **LiqPay (ПриватБанк)** чи **WayForPay** / **RozetkaPay**?
   - Чи погоджується механіка **Escrow Hold** (холдування коштів покупця до моменту успішного вручення посилки перевізником за статусом ЕН)?
3. **Фіскалізація та програмні РРО (COM-3 / FSC-1):**
   - Який сервіс ПРРО обирається: **Checkbox** (checkbox.ua) чи **Вчасно.Каса** (vchasno.ua)?
   - Яка схема емісії чека затверджена:
     - `Схема 1`: Платформа видає чек/акт на власну комісію; ФОП-продавець видає фіскальний чек на вартість товару.
     - `Схема 2`: Платформа автоматично формує повний електронний фіскальний чек за API через Checkbox від імені каси ФОП-продавця.
4. **Первинні документи виплат (FIN-2):**
   - Який графік виплат затверджено: **T+3 після підтвердження вручення** чи щовівторка за зведеним реєстром?
   - Який документ є підставою для списання та перерахування: електронний **Звіт повіреного** чи **Акт наданих послуг**?

## 4. Опитувальник для Керівника логістики та Операційного директора (Logistics Questionnaire)

> **Мета:** Автоматизація відправлень, контроль статусів доставки та тригери виплат.

1. **Договір з Новою Поштою (LOG-1):**
   - Чи укладено генеральний корпоративний договір між ТОВ/ФОП платформи «ЛАЙФ» та ТОВ «Нова Пошта»?
   - Чи отримано бойовий API-ключ для генерації Експрес-Накладних (ЕН) через API v2.0?
2. **Ланцюжок трекінгу як фінансовий тригер (LOG-1 / FIN-2):**
   - Підтвердіть, що статус Нової Пошти `9 (Відправлення отримано)` є єдиним автоматичним тригером для переведення замовлення в статус `completed` та розблокування виплати майстру у `SettlementBatch`.
   - _Відповідь:_ `[ ] Підтверджено`
3. **Обробка відмов та повернень (LOG-2):**
   - У разі відмови покупця у відділенні (статуси `102 / 103`): за чий рахунок здійснюється зворотна доставка товару майстру?
