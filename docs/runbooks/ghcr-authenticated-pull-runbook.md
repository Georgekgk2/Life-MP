# Інструкція безпечної автентифікації GHCR на Production Хості

- **Статус:** ОПЕРАЦІЙНИЙ РЕГЛАМЕНТ
- **Дата створення:** 2026-09-12
- **Призначення:** Забезпечення захищеного завантаження приватних контейнерів із GitHub Container Registry (GHCR) на сервер без витоку облікових даних.

---

## 1. Суворі заборони (Anti-Patterns & Prohibitions)

Категорично забороняється:
- Шукати токени чи паролі в історії команд розробника (`~/.zsh_history`, `~/.bash_history` тощо);
- Передавати токени або паролі як аргументи командного рядка чи інлайн у SSH-командах (вони стають видимими у `ps aux`, системних логах та журналах терміналів);
- Передавати секретні ключі чи токени в тексті чату з AI-асистентами;
- Перемикати репозиторій або контейнерні пакети у статус `PUBLIC` для обходу авторизації чи білінгу;
- Зберігати довгоживучі credentials у незахищених текстових файлах на сервері чи локальній машині.

---

## 2. Стандартний регламент створення облікових даних (Owner-Only)

1. **Генерація токена з мінімальними правами (Principle of Least Privilege):**
   - У налаштуваннях GitHub (`Settings → Developer settings → Personal access tokens → Fine-grained tokens`);
   - Обмежити доступ виключно репозиторієм `Georgekgk2/Life-MP`;
   - Права: **лише `read:packages`** (жодних прав на читання коду, адміністрування чи секретів);
   - Термін дії: короткостроковий (до 30 днів або на час релізу).

---

## 3. Рекомендований спосіб автентифікації на хості

### Варіант А: Інтерактивний логін власником (Рекомендований)

Власник самостійно запускає термінальну сесію з хостом:
```bash
ssh jorvis-prod-vm
docker login ghcr.io -u Georgekgk2
# Ввести токен інтерактивно при запиті Password:
exit
```
Токен зберігається у зашифрованому/захищеному локальному конфігу Docker хоста (`~/.docker/config.json`, права `0600`).  
Після цього будь-яка автоматизована промоція виконує `docker pull` без передачі токенів через мережу чи аргументи.

---

### Варіант Б: Ізольований файл конфігурації з правами 0600

Якщо необхідний headless-деплой без інтерактивного введення:
1. Токен розміщується у файлі секретів хоста (наприклад `/etc/docker/ghcr-token`), доступному **виключно користувачу root/docker з правами `0600`**;
2. Автентифікація виконується виключно через стандартний потік введення:
   ```bash
   cat /etc/docker/ghcr-token | docker login ghcr.io -u Georgekgk2 --password-stdin
   ```
3. Після завершення операції завантаження:
   ```bash
   docker logout ghcr.io
   ```
