# Локальні сервіси даних

`docker-compose.dev.yml` призначено **лише для локальної розробки**. Він запускає тільки два сервіси даних:

- `postgres` на PostgreSQL 16;
- `redis` на Redis 7.

Файл не збирає і не запускає storefront, commerce, CMS чи будь-який інший застосунок. Він не є staging- або production-конфігурацією, не містить production-секретів і прив’язує обидва порти лише до `127.0.0.1`, тому вони не доступні з локальної мережі.

## Передумови

Потрібен Docker Compose v2, запущений через Docker Desktop або OrbStack. Для запуску застосунків окремо також потрібні Node.js 22 і `pnpm`.

## Запуск і зупинка

Із кореня репозиторію:

```sh
make dev-infra-up
```

Compose створить іменовані Docker volumes і запустить сервіси у фоні. Стан healthcheck можна побачити так:

```sh
docker compose -f docker-compose.dev.yml ps
```

Журнали обох сервісів:

```sh
make dev-infra-logs
```

Зупинити сервіси, **зберігши** дані в іменованих volumes:

```sh
make dev-infra-down
```

Застосунок запускається окремо від інфраструктури:

```sh
pnpm dev
```

## Локальні підключення

| Сервіс | Адреса | Локальні параметри |
| --- | --- | --- |
| PostgreSQL 16 | `127.0.0.1:54329` | База: `life_local`; користувач: `life_local`; пароль: `life_local_password` |
| Redis 7 | `127.0.0.1:56379` | Автентифікація навмисно не налаштована; порт доступний лише через loopback |

У `.env.example` наведено відповідні не-секретні локальні URL:

```dotenv
DATABASE_URL=postgresql://life_local:life_local_password@127.0.0.1:54329/life_local
REDIS_URL=redis://127.0.0.1:56379
```

За потреби локальний застосунок може отримати ці значення так:

```sh
cp .env.example .env
```

`docker-compose.dev.yml` не покладається на `.env`; значення в ньому навмисно фіксовані для безпечного локального старту. Не використовуйте ці облікові дані поза власним комп’ютером і не додавайте до цього файлу реальні секрети.

## Локальні дані та руйнівні команди

`make db-backup` створює дамп PostgreSQL у `backups/`; ця директорія ігнорується Git.

Наведені нижче команди є **лише локальними** й руйнівними. Кожна виводить попередження та вимагає явного підтвердження:

- `make db-restore FILE=backups/файл.sql` — перезаписує дані PostgreSQL із дампу;
- `make db-reset` — видаляє volumes PostgreSQL і Redis, а потім знову запускає сервіси;
- `make docker-clean` — зупиняє сервіси й видаляє їхні volumes.

## Staging і production

Для цього репозиторію не реалізовано жодної операції розгортання. `make deploy-staging` і `make deploy-production` навмисно завершуються з ненульовим кодом і повідомленням про те, що розгортання не реалізоване. Не використовуйте цей Compose-файл для staging або production.
